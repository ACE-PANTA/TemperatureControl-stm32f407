## 1. 硬件连接

### 网络连接设置 (直连 PC)

设备默认配置为 **静态 IP**，不会自动获取 IP 地址。连接前需要先配置 PC：

**步骤 1: 物理连接**
- 用网线把 STM32 开发板的 RJ45 网口直接插到 PC 网口
- 检查 LAN8720A 芯片旁的 Link LED（绿灯）是否**常亮**

**步骤 2: 配置 PC 静态 IP**
1. 打开 **控制面板 → 网络和共享中心 → 更改适配器设置**
2. 右键 **以太网** → 属性 → **Internet 协议版本 4 (TCP/IPv4)**
3. 选择 **"使用下面的 IP 地址"**，填入：
   - IP 地址: `192.168.1.10`
   - 子网掩码: `255.255.255.0`
   - 默认网关: 留空
4. 点确定

**步骤 3: 验证**
```bash
ping 192.168.1.100
```
通的话会显示 `Reply from 192.168.1.100: bytes=32 time<1ms TTL=64`

如果 ping 不通: 检查防火墙（临时关闭试试），网线是否插好，Link LED 是否亮。

**步骤 4: TCP 连接**
```bash
# netcat (推荐)
nc 192.168.1.100 8000

# 或 PuTTY: Connection type=Raw, Host=192.168.1.100, Port=8000
```

### 连接路由器

如果通过路由器连接，确保:
- 路由器 LAN 网段是 `192.168.1.x`
- `192.168.1.100` 没有被其他设备占用
- 不满足条件时，用串口发送 `!NET=...` 修改 IP，再 `!SAVE` 保存

## 2. 控制架构

```
┌─ 远区 |error| > 阈值 ────────┐    ┌─ 近区 |error| ≤ 阈值 ─────┐
│                              │    │                           │
│  串级控制器 (Cascade)         │    │  分层增量PID        │
│  外环: 温度误差 → 升温速率    │    │                           │
│  内环: 速率误差 → PWM         │    │  2~5°C:     每秒更新PID    │
│  输出: 绝对 PWM               │    │  0.5~2°C:   慢速更新(默认15s)     │
│                              │    │  ±0.5°C:    死区,不动     │
└──────────────────────────────┘    └───────────────────────────┘
              ↓                              ↓
              └──────────┬───────────────────┘
                         ↓
                   My_Ctr (PWM 映射)
                   正数 → 加热 (0~100%)
                   负数 → 风扇 (25~100%)
```

### 为什么这样设计

热系统有**大时延**：输出 PWM 后温度变化要几十秒才能稳定。传统 PID 算出的绝对值经常在环境变化后失效，导致稳态误差。

- **远区用串级**：误差大时全功率逼近，速率内环响应极快
- **近区分层增量PID**：2~5°C每秒调整快速逼近；0.5~2°C按配置间隔微调(默认15s)避免PWM反复跳；±0.5°C死区PWM完全不动，消除稳态振荡

### 分层控制策略

```
|error| > 5°C          串级控制器 (全速)
    ↓
2°C < |error| ≤ 5°C    增量PID, 每秒更新 (正常调)
    ↓
0.5°C < |error| ≤ 2°C  增量PID, 慢速更新 (默认15s, 可配hyb_slow_interval)
    ↓
|error| ≤ 0.5°C        死区, PWM 完全不动
```

| 层级 | 误差范围 | 更新频率 | 单步限幅 | 行为 |
|---|---|---|---|---|
| 远区 | >5°C | — | — | 串级全速逼近 |
| 正常近区 | 2~5°C | 每秒 | ±15% | 快速响应, 消除大偏差 |
| 慢速区 | 0.5~2°C | 每N秒 | ±5% | 慢慢微调, 避免 PWM 反复跳 |
| 死区 | ≤0.5°C | 不更新 | 0 | PWM锁死, 消除稳态振荡 |

> **慢速区间隔** 由 `hyb_slow_interval` 控制 (默认15s, 范围3~60)。
> 通过 `!HYBRID=5.0,3.0,0.3,1.0,20` 第5个参数调整。
> **死区宽度** 由代码 `HYBRID_DEADZONE` 宏控制 (默认0.5°C), 需重编译修改。
>
> **单步限幅** (防振荡): 正常区 +8%/-4%/s, 慢速区 +3%/-2%/s。
> 涨幅比降幅宽, 热系统降PWM太快会过冲->振荡->反复跳变。
> 限幅值在 `My_PID_Ctr()` 中修改 `d_up` / `d_down`。

## 4. 指令协议

### 帧格式

```
请求: !CMD=VALUE*XX\r\n
回复: !ACK=OK*XX\r\n    (成功)
      !ACK=ERR*XX\r\n   (失败)
      !响应内容*XX\r\n   (查询结果)
```

- `!` 帧头, `*XX` 校验和, `\r\n` 帧尾
- 校验和 = 从 `!` 到 `*` 之前所有字节的 XOR
- **串口 (USART1) 和网口 (TCP:8000) 使用完全相同的协议**
- 串口发来的命令回复走串口，网口发来的回复走网口

### 指令列表

#### 系统控制

| 指令 | 示例 | 说明 |
|---|---|---|
| `!MODE=AUTO` | `!MODE=0*34\r\n` | 切换到自动温控 |
| `!MODE=MAN` | `!MODE=1*35\r\n` | 切换到手动 PWM |
| `!TEMP=58.0` | `!TEMP=58.0*15\r\n` | 设置目标温度 (仅自动模式) |
| `!PWM=50` | `!PWM=50*12\r\n` | 设置手动 PWM (仅手动模式) |
| `!STEP=5` | `!STEP=5*13\r\n` | 设置按键步进 (1/5/10) |

#### 控制器调参

| 指令 | 示例 | 说明 |
|---|---|---|
| `!PID=1.15,0.005,0.0` | — | 设置传统 PID 参数 |
| `!CASCADE=0.5,3.0,40,12` | — | 串级: K_outer, MaxRate, Kp_inner, Ki_inner |
| `!HYBRID=5.0,3.0,0.3,1.0,15` | — | 混合: Threshold, Kp, Ki, Kd, SlowInterval |

#### 网络配置 (修改后需重启)

| 指令 | 示例 |
|---|---|
| `!NET=192.168.1.100,192.168.1.1,255.255.255.0,8000` | 设置 IP/网关/掩码/端口 |
| `!MAC=02:00:00:00:00:01` | 设置 MAC 地址 |

#### 查询

| 指令 | 回复示例 |
|---|---|
| `!GET=STATE` | `STATE=MODE:0,PWM:35,GOAL:580,FB:575` |
| `!GET=PID` | `PID=KP:1.1546,KI:0.0054,KD:0.0000` |
| `!GET=CASCADE` | `CASCADE=KO:0.50,MR:3.0,KPI:40.0,KII:12.0` |
| `!GET=HYBRID` | `HYBRID=TH:5.0,KP:3.00,KI:0.300,KD:1.00,INT:15` |
| `!GET=NET` | `NET=IP:192.168.1.100,GW:192.168.1.1,NM:255.255.255.0,PORT:8000` |
| `!GET=ETH` | `ETH=LINK:1,PHY:0,ERR:0,PHYID:0007C0F1,RX:5,TX:5,ARP:2,ICMP:3,TCP:0` |
| `!GET=CONFIG` | 逐条返回所有配置参数 |

#### 持久化

| 指令 | 说明 |
|---|---|
| `!SAVE` | 立即保存当前配置到 Flash |
| `!RESET` | 恢复出厂默认值 (保留 MAC 地址) |

> **注意**: 修改参数后会自动延迟 500ms 保存到 Flash。`!SAVE` 是立即保存。

## 5. STATE 字段说明

查询 `!GET=STATE` 返回:

```
STATE=MODE:0,PWM:35,GOAL:580,FB:575
```

| 字段 | 含义 | 说明 |
|---|---|---|
| MODE | 模式 | 0=自动, 1=手动 |
| PWM | 当前 PWM | -100~100, 正=加热, 负=风扇 |
| GOAL | 目标温度×10 | 如 580 = 58.0°C |
| FB | 当前温度×10 | 如 575 = 57.5°C |

### ETH 诊断字段 (GET=ETH 返回)

```
ETH=LINK:1,PHY:0,ERR:0,PHYID:0007C0F1,RX:5,TX:5,ARP:2,ICMP:3,TCP:0
```

| 字段 | 含义 | 说明 |
|---|---|---|
| LINK | 物理连接 | 1=网线已连接, 0=未连接 (网线拔了?) |
| PHY | PHY 芯片地址 | 0 或 1, 255=未找到 PHY 芯片 |
| ERR | 错误码 | 0=正常, 详见错误码表 |
| PHYID | 芯片型号 | 如 0007C0F1=LAN8720A, 00000000=未检测到 |
| **RX** | **收包数** | **收到并处理的帧 (ping 时应增长)** |
| **TX** | **发包数** | **发出的帧** |
| **ARP** | **ARP 回复** | **每次 ARP 请求回复一次** |
| **ICMP** | **Ping 回复** | **每次 ping 回复一次** |
| ANEG | 自协商 | 1=完成, 0=超时/未完成 |
| TCP | 客户端 | 1=有客户端连接, 0=无连接 |

### 以太网错误码

| 错误码 | 定义 | 含义 | 解决方法 |
|---|---|---|---|
| 0 | `ETH_ERR_OK` | 正常, 链路已建立 | — |
| 1 | `ETH_ERR_NO_PHY` | 找不到 PHY 芯片 | 检查 PHY 焊接/供电/晶振; 确认 PHY 地址 |
| 2 | `ETH_ERR_NO_LINK` | PHY 找到但网线无连接 | 检查网线是否插好; 对端设备是否上电 |
| 3 | `ETH_ERR_ANEG_TIMEOUT` | 自协商超时 | 检查 RMII 时钟 50MHz; 检查 PHY 晶振 |
| 4 | `ETH_ERR_NOT_INITED` | ETH 模块从未初始化 | Eth_Init() 未被调用或编译未包含 eth.c |

### 串口诊断网口故障

**这是推荐做法**——网口有问题时通过串口排查。上位机软件可以自动诊断:

```
第一步: 确认当前网络配置
  发送: !GET=NET
  回复: NET=IP:192.168.1.100,GW:192.168.1.1,NM:255.255.255.0,PORT:8000

第二步: 获取详细诊断
  发送: !GET=ETH
  回复: ETH=LINK:0,PHY:0,ERR:2,PHYID:0007C0F1,RX:0,TX:0,ARP:0,ICMP:0,TCP:0

  解读示例: LINK=0, ERR=2     → 网线没插好
           PHYID=00000000     → PHY 芯片没找到, 硬件问题
           LINK=1, RX=0       → 链路通但没收包, RMII/MAC配置问题
           LINK=1, ICMP>0     → ping 通了!
           LINK=1, TCP=0      → 网络正常, 无客户端连接
           ERR=4               → 固件没编译以太网模块
```

| 故障现象 | 串口 `!GET=ETH` 返回 | 根因 | 解决 |
|---|---|---|---|
| ping 不通 | `ERR:2` | 网线没插 / 断线 | 插紧网线, 检查 Link LED |
| ping 不通 | `ERR:1,PHY:255,PHYID:00000000` | PHY 芯片未找到 | 硬件焊接/供电/晶振 |
| ping 不通 | `ERR:3` | RMII 时钟异常 | 检查 50MHz 时钟源 |
| LINK=1 但 ping 不通 | `LINK:1,RX:0` | 帧没收进来, RMII/MAC 问题 | 检查 MII_RMII_SEL, 50MHz 时钟 |
| LINK=1 但 ping 不通 | `LINK:1,RX:5,ICMP:0` | 收到帧但未处理ICMP | IP不匹配? 帧被过滤? |
| ping 通但连不上 | `LINK:1,TCP:0` | 防火墙拦截 TCP | 检查 PC 防火墙 8000 端口 |
| 一切正常 | `LINK:1,ERR:0,TCP:1` | ✓ 完全正常 | — |

## 6. 快速开始

### 首次上电

```
1. 默认手动模式, 目标温度 30°C
2. 连接串口 (115200 8N1) 或网口 (nc 192.168.1.100 8000)
3. 发送 !MODE=AUTO 进入自动温控
4. 发送 !TEMP=58.0 设置目标
5. 观察温度: >5°C串级全速 → 2~5°C每秒PID → 0.5~2°C慢速PID → ±0.5°C死区锁定
```

### 调参流程

```
1. 先调远区速度:
   !CASCADE=0.5,3.0,40,12      (默认值)
   升温太慢 → 增大 max_heat_rate (如 5.0)
   升温过冲 → 减小 k_outer (如 0.3)

2. 再调近区精度 (分层增量PID):
   !HYBRID=5.0,3.0,0.3,1.0,15    (默认值, 第5参数=慢速间隔)
   死区太宽温度差0.3°C也不动 → 改 HYBRID_DEADZONE (需重编译)
   慢速区 15 秒改一次还是快  → `!HYBRID=5.0,3.0,0.3,1.0,25` 第5参数调大
   慢速区 PWM 变化幅度太大   → 改慢速区单步限幅 (需重编译)
   温度不到目标, PWM涨太慢   → 增大 hyb_ki (如 0.3→0.6)
   温度过冲超过目标           → 增大 hyb_kd (如 1.0→3.0)
   PWM 大幅振荡 (0->100->0)   → 收紧 d_down (降幅限制); 增大 hyb_kd
   2~5°C 区小幅振荡          → 减小 hyb_kp (如 3.0->1.5)

3. 保存参数:
   !SAVE
```

### 网口测试

```
电脑端:
  nc 192.168.1.100 8000
  输入: !GET=STATE
  应返回: STATE=MODE:1,PWM:0,GOAL:300,FB:255

  ping 192.168.1.100
  应能 ping 通
```

## 8. 故障排查

| 现象 | 可能原因 | 解决 |
|---|---|---|
| 温度卡在目标以下 | 积分太弱 / 限幅太严 | 增大 hyb_ki (如 0.3->0.6) 或放宽 d_up |
| 温度超调严重 | 远区太猛 / Kd不够 / 降PWM太快 | 减小 csc_max_heat_rate; 增大 hyb_kd(1->3); 收紧 d_down |
| 近区PWM大幅振荡(0<->100) | 步长限幅太松 / Kd太小 | 收紧 d_up/d_down; 增大 hyb_kd (1->3) |
| 网口连不上 | IP 不匹配 / 硬件问题 | 串口发 `!GET=ETH` 看错误码, 对照上面诊断表 |
| Flash 保存失败 | 扇区擦写错误 | 检查 FLASH_Sector_7 未被占用 |
| 编译 ETH 相关错误 | 库文件缺失 | 确认 RCC/GPIO 头文件包含, C99 关闭 |
